# mgxrl — Trust-Weighted Resilient Consensus Control for Microgrids

A physics-structured reinforcement learning framework for attack-resilient
distributed secondary control, with verified explanation interfaces.

The policy emits **per-source trust weights** on the consensus communication
graph. The published consensus controller stays in the loop at all times and is
recovered exactly at zero action, so the residual structure is the nominal-case
stability argument rather than a claim bolted on afterwards.

**Paper:** E. E. Ogar and S. Chaitusaney, *Trust-Weighted Resilient Consensus
Control for Microgrids: A Physics-Structured Reinforcement Learning Framework
with Verified Explanation Interfaces* (submitted to *Results in Engineering*).

**Archived release of this repository:** doi:[10.5281/zenodo.24134204](https://doi.org/10.5281/zenodo.24134204)
(cite the concept DOI; it always resolves to the latest version).

**Companion dataset:** the 280-run synthetic detector corpus generated by this
code, doi:[10.5281/zenodo.24082859](https://doi.org/10.5281/zenodo.24082859).

**Builds on and is distinct from:** Ogiesoba-Eguakun & Rath, *Cyberattack
Detection in Virtualized Microgrids Using LightGBM and Knowledge-Distilled
Classifiers*, and its IEEE DataPort release, doi:10.21227/bmtr-fr76. That work
does detection. This does control, plus explanation, plus a forensic account of
what the released dataset can and cannot support.

---

## What this is not

Stated first, because an earlier draft's title claimed more.

- **Not predictive.** No forecast, no prediction horizon, no learned dynamics
  model, no rollout. The policy is a reactive residual over a four-frame
  history stack. A history stack is not prediction.
- **Not physics-informed in the PINN sense.** No physics-informed loss, no
  learned dynamics, no Lyapunov constraint. Physics enters through the plant,
  the reward references, the residual structure and the graph-structured action
  space. The accurate term is *physics-structured residual RL*.
- **The natural-language interface is a negative result.** A deterministic
  template beats all four local language models on grounded-content coverage at
  equal numeric fidelity. There is no human-subject study, so no operator
  benefit is claimed in either direction.
- **The detector is not in the control loop.** `include_detector` defaults to
  `False`; every reported run has `obs_dim = 320`. Detector and controller are
  independent, so a detector false positive cannot propagate into a control
  action.

## Headline results

Ranges are across the three independent training seeds, each evaluated on the
same twenty paired evaluation seeds (`results/eval3_s0..2`). The paper reports
the range, not the best run.

| | |
|---|---|
| Ramp attack, return | +23,081 to +44,415; 16–20 of 20 evaluation seeds improved; paired *t* 4.7–12.2 |
| Additive attack, return | +14,367 to +26,716; 11–20 of 20 improved; paired *t* 2.9–12.2 |
| Frequency RMSE under Ramp | −58.8 % to −96.5 % |
| Voltage-limit violations under Ramp | 3.46 % nominal → 0.00 %, 0.59 %, 6.63 % (two seeds improve, one worsens) |
| Normal and DoS | return degrades on every seed (0–1 of 20 improved) |
| Detector macro-F1 (synthetic corpus) | 0.9987 random split → 0.7568 run-level holdout |
| Explanation coverage | template 0.91, best LLM 0.68, chance floor 5.6 % |
| Fidelity against the release, primary layer | direction agrees, correlation 0.9368 |

**Two classes are out of reach and the paper says why.** Denial of service and
Coordinated Stealth are not identifiable from any per-step feature — 0.112 and
0.370 accuracy against references of 0.110 and 0.314. That is the attacks
behaving as specified, not the method failing, and it is established *before*
training rather than discovered after.

**The cost is structural.** The trained policy holds 2.7–4.7 sources below full
trust during healthy operation, and 50–63 % of action components sit in the
reward-flat region a ≥ 0 (0.500, 0.574, 0.630 across seeds). Two independent
knobs at matched budgets failed to move the standing distrust. A trust weight
acts on the signal *before* it enters the consensus update, so a source trusted
at onset has already injected a corrupted value; standing distrust is the only
way to be protected at onset.

**No secondary-layer gain defends against a consensus bias.** Measured across a
20× range of attack amplitude, a 4× range of droop coefficient and nine ring
sizes, the steady-state displacement is

```
spread = floor((n-2)/2) * ceil((n-2)/2) / n * bias_xi / m_droop
```

exact at every point tested. It contains no control gain: 30× on `c_f` and 8×
on `k_p` leave it unchanged, and the latter degrades settling by 4×. Integral
action drives the error to zero against a *corrupted reference*, so higher gain
reaches the wrong equilibrium faster. This is the analytic case for acting on
the signal before the consensus update. The closed form is measured, not
derived.

## Quick start (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-lock.txt
python -m pytest tests\ -q
.\reproduce_all.ps1 -Dataset C:\path\to\Dataset -SkipTraining
```

Expect `23 passed` from the tests. `requirements-lock.txt` pins the exact
versions the reported results were produced with (Python 3.14.6). The trained
agents are Stable-Baselines3 archives and load reliably only with the pinned
versions.
Full installation, including MATLAB, is in `SETUP.md`.

`reproduce_all.ps1` runs every experiment in dependency order and stops at the
first failure rather than letting a later stage consume a stale input. Roughly
4–6 hours with `-SkipTraining`, 9–11 without. Running end to end is not by
itself verification: compare the numbers it writes against the paper.

If PowerShell refuses to run the script:
`Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`

**Which file is authoritative.** The `plant:` section of
`configs/microgrid.yaml` is the single source of truth for plant parameters;
`scripts\08_sync_matlab_params.py` regenerates `matlab\mg_params.m` from it, so

is not read by training: `RewardWeights` in `src/mgxrl/envs/resilient_env.py`
is authoritative for the reward.

**Archived runs.** `runs/ppo3_s0..2` are the three reported training seeds.
They are bit-identical (every policy parameter, max abs difference 0.0) to
`ppo2_s0..2` from an earlier, separately dated campaign, so retraining from
the same seed reproduces the policy exactly; only `ppo3` is archived because
only it records its own `train_config.json`. `runs/wact3`, `runs/wact10` and
`runs/pnorm50_5M` are the invariance experiments (Fig. 15, Table 9).
Intermediate checkpoints are not archived.

**Archived results.** `results/eval3_s0..2` back Table 8 and Fig. 13;
`eval3_s0_check` is an independent rerun of `eval3_s0`. The top-level
`detector_protocols.*` backs Table 10. `explain_*` back the explanation
ablation, and `wact3`, `wact10` and `pnorm50_5M` Table 9. `release_clean`,
`release_detector` and `shortcut_probe.json` back findings 2 and 3 in
`FINDINGS.md`. The `fidelity_tierC*.csv` files hold what the paper calls
**Tier B**; the file names predate the renaming and are kept because
`06_validate_against_dataset.py` writes them. Older evaluation and exploratory
folders evaluated superseded checkpoints, protocols or settings and are
deliberately excluded.

## Pipeline

### 1 — Release forensics

Reads the public release only. Bounds what any later fidelity claim may assert.

```powershell
python scripts\10_inspect_release.py --root <DATASET> --settle 0.15 --out results
python scripts\11_check_csv_integrity.py --root <DATASET>
python scripts\12_shortcut_probe.py --root <DATASET> --mode magnitude --out results
python scripts\14_preonset_identity_probe.py --dataset <DATASET>
python scripts\15_release_channel_identity.py --dataset <DATASET>
```

### 2 — Detector corpus and leakage-corrected benchmark

The release is 1.00 s per scenario, one run each. Run-level holdout requires
more than one run, so it is impossible on the release itself.

```powershell
python scripts\09_generate_detector_dataset.py --out data\synthetic --runs 40 --seconds 8.0 --log-dt 0.001 --seed 0
python scripts\01_detector_benchmark.py --root data\synthetic --decimate 1 --windowed --repeats 3 --out results
python scripts\01_detector_benchmark.py --root <DATASET> --decimate 500 --drop-corrupt --repeats 10 --trim 0.15 --out results\release_clean
```

### 3 — Plant fidelity (two tiers)

```powershell
python scripts\08_sync_matlab_params.py
python scripts\05_export_reference_traj.py --out results --seconds 12.0
matlab -batch "cd matlab; validate_fidelity"
matlab -batch "cd matlab; check_inner_loops"
python scripts\06_validate_against_dataset.py --root <DATASET> --decimate 100 --primary 0.05 --out results
```

**Tier A** — reduced-order plant against an independent stiff-solver reference
(MATLAB `ode23tb`) implementing the same equations with inner voltage loops.
Tests discretisation and the algebraic-voltage assumption. Passes on all seven
classes, f-RMSE 4e-8 … 5e-5 Hz. The inner loops contribute about 18 % of the
residual, so this is principally a discretisation check.

**Tier B** — against the IEEE DataPort release, differentially on both sides.
The release contributes attacked-minus-Normal; the plant contributes
attacked-minus-unattacked at the same seed. The energisation transient is
common to each pair and cancels exactly, so **no baseline window is chosen
anywhere**. A pre-onset gate admits five of six classes; DoS is excluded
(see `FINDINGS.md`, finding 6). Only the primary, droop-dominated layer is
validated (see finding 5).

A **switching-level tier is deliberately not part of the programme.** The
averaging assumption is standard in the distributed secondary-control
literature and is why a reduced-order model is admissible at all; verifying it
against a second simulation is a weaker test than the hardware validation
listed as future work.

### 4 — Mechanism

Plant-only. Produces the scaling law.

```powershell
python scripts\16_injection_point_probe.py --root <DATASET> --long 3.0 --out results
python scripts\17_settling_timescale.py --root <DATASET> --attack Additive --span 3.0 --out results
python scripts\18_cf_sweep.py --root <DATASET> --values 10,20,50,100,200,300 --span 3.0 --out results
python scripts\19_param_sweep.py --root <DATASET> --param m_droop --values 0.785,1.571,3.142 --span 20 --out results
python scripts\20_attack_scaling.py --attr bias_xi --values 0.05,0.1,0.2,0.3,0.6,1.0 --span 20 --out results
python scripts\21_topology_scaling.py --values 6,8,10,12,14 --span 200 --out results
```

### 5 — Admissibility, training, evaluation

Three pre-training tests. **All three fail silently and look identical from the
training curve**, which is why they run before the compute is committed.

| Test | Question | Where |
|---|---|---|
| Expressiveness | Can *any* action cancel the attack? | `test_oracle_action_can_cancel_an_attack` |
| Affordability | Is exploration cheap when nothing is wrong? | `test_exploration_is_cheap_when_nothing_is_wrong` |
| Observability | Is the attacked source identifiable at all? | `scripts/13_observability_probe.py` |

```powershell
python scripts\00_calibrate_reward.py --episodes 30 --sep-seeds 10 --out results
python scripts\13_observability_probe.py --episodes 60 --repeats 3 --out results
python scripts\02_train_agent.py --timesteps 5000000 --n-envs 8 --seed 0 --outdir runs\ppo3_s0
python scripts\03_evaluate.py --agent runs\ppo3_s0\agent_final.zip --vecnorm runs\ppo3_s0\vecnormalize.pkl --seeds 20 --out results\eval3_s0
python scripts\22_fig14_ramp_trajectory.py --agent runs\ppo3_s0\agent_final.zip --sweep-dir results\eval3_s0 --out results\fig14
```

Report `agent_vs_nominal_paired.csv`, not the percentage table.

`22_fig14_ramp_trajectory.py` reruns the median Ramp evaluation episode in both
arms and records the per-step measurements behind Fig. 14. It reproduces the
stored sweep exactly (returns −69,079 and −26,749; 1,051 and 1,200 steps), so
the figure shows an episode inside Table 8, not a separate demonstration.
An episode terminates early, and is counted as collapsed, if any DG frequency
deviates from nominal by more than 0.5 Hz, if any terminal voltage leaves
0.5–1.5 pu, or if any state becomes non-finite.

### 6 — Explanation

```powershell
python scripts\04_explain.py --agent runs\ppo3_s0\agent_final.zip --vecnorm runs\ppo3_s0\vecnormalize.pkl --n-states 100 --n-explanations 100 --no-llm --out results\explain_template
python scripts\04_explain.py --agent runs\ppo3_s0\agent_final.zip --vecnorm runs\ppo3_s0\vecnormalize.pkl --n-states 100 --n-explanations 100 --llm llama3:8b --timeout 300 --prompt-variant baseline --reuse-faithfulness --out results\explain_llama3_8b
```

Repeat the second line for `llama3.1:8b`, `llama3.2:3b` and `mistral-nemo`.
`--reuse-faithfulness` after the first run: the battery is 100 states of
integrated gradients plus deletion curves and does not depend on the generator.

### 7 — Export

```powershell
pip install onnxscript
python scripts\07_export_onnx.py --agent runs\ppo3_s0\agent_final.zip --vecnorm runs\ppo3_s0\vecnormalize.pkl --out runs\ppo3_s0\actor.onnx
```

Exports the deterministic mean with a **clamp, not tanh** — SB3 uses
`squash_output=False`, and `tanh(-1) = -0.76`, so exporting tanh would deliver
24 % trust where full isolation was commanded.

## Findings about the public release

Six, all in `FINDINGS.md`, all reproducible from `scripts/10–17` and `06`.

1. **Solver divergence** in 6 of 7 files, per-file signature, values to 8.2e152.
   The CSVs are structurally perfect; the source model diverged and it was
   faithfully recorded.
2. **The corruption artifacts are an exploitable fingerprint** — nine artifact
   flags alone reach block-split macro-F1 0.385 and identify SlowRamp at 0.93;
   keeping the corrupted channels lifts a detector from 0.658 to 0.782.
3. **Leakage** — on 33 clean features, random split 0.990 against block split
   0.658; Stealth and SlowRamp fall from above 0.98 to 0.39 and 0.46.
4. **Structure** — 1.00 s per scenario, one run each, cold start from zero
   initial conditions, attack window t ∈ [0.5005, 0.801] s. Frequency has not
   restored within the record; an author has confirmed that their secondary
   restoration runs beyond one second, so this is a slow secondary layer rather
   than an absent one.
5. **The release cannot validate a secondary layer.** Its restoration outlasts
   its own record, so the attack's effect on secondary control never develops
   inside the data.
6. **The DoS file is not the same simulation as the others.** It differs from
   Normal from the first sample with no step at onset — gate ratio 0.92 against
   a floor of 10 — so no differential against it is defensible.

Findings 1–3 were sent to the dataset authors before publication; they are
revising a preprint and have the integrity output.

## The recurring lesson

In **six** separate cases a metric reported a clean number while measuring the
wrong quantity: evaluation without VecNormalize, a false-trigger rate measuring
`max|a|`, an unimplemented connectivity floor, an observation missing the
consensus innovation, a test scoring a formula the reward had stopped using,
and a hallucination checker anchored on the wrong reference.

Every one was found by **giving the metric a null or a control**, not by
inspecting code. A script that runs end to end without erroring would have
reported all six as fine.

## Known issues

- `Early stopping at step 0 due to reaching max kl` on nearly every update.
  `target_kl = 0.03` fires before the first epoch, so `n_epochs = 5` is nominal.
  Working as intended, and stated here rather than left for a reviewer to find.
- `overflow encountered in reduce` on release loads is the known solver
  divergence (finding 1). `P_DG*`, `Q_DG*` and `f_DG*` are clean, verified
  finite.
- Block-split multiclass macro-F1 on the release varies widely across repeats
  (standard deviation about 0.1 over ten repeats). Block splitting strands whole classes on a
  one-second recording; more repeats will not fix it. Report it with that
  caveat or not at all.
- LightGBM `eval_set` deprecation warnings are harmless.
- `build_reference_model.m` has never been run against live MATLAB;
  `setChartScript` uses the Stateflow `sfroot` API and is the likely failure
  point. Manual fallback in `SETUP.md`.
- `deploy_policy.m` attaches to a model built from `mg_dynamics` under ode23tb —
  the same equations as Tier A. It is a solver check, not a fidelity result. It
  also never applies the observation normalisation it constructs, and passes
  `MaxSteps 600` against a 1,200-step episode. No result in the paper uses it.
- `_detector_features` is implemented and guarded but untested, because no test
  constructs the environment with `include_detector=True`. Wiring a detector
  into the loop needs a corpus regenerated at `--log-dt 0.01`: the benchmark's
  20-sample window spans 20 ms there and 200 ms in the environment.
